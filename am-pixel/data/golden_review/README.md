# data/golden_review/

Golden Dataset triage workspace. Generated by `tools/run_triage_scorer.py`.

## Structure

```
golden_review/
├── scores.json              — Per-sprite rubric scores + bucket assignments
├── curation_log.jsonl       — Append-only log of all Accept/Reject/Flag decisions
├── A_autopass/              — Score ≥ 85 — highest-priority review queue
├── B_borderline/            — Score 70–84 — review after A bucket
├── C_autoreject/            — Score < 70 — review last / spot-check only
├── D_anomaly/               — Anomaly heuristics fired — inspect carefully
└── E_tileset/               — Tileset sprites — separate track (SPEC_PENDING_032)
```

## Buckets

**A — Autopass (score ≥ 85):** Passed the automated rubric gate. Review these first — highest
density path to building the Golden Dataset. Still requires your explicit Accept.

**B — Borderline (score 70–84):** Close to passing. Review after A bucket is exhausted or
if the A bucket yield is below target.

**C — Autoreject (score < 70):** Failed the automated gate. Spot-check only — looking for
cases where the rubric was too strict. Any sprite you accept here will strengthen the
calibration report.

**D — Anomaly:** Three heuristics:
- H1: Top-5% score despite having failure mode flags (suspicious high scorer)
- H2: Bottom-10% outlier in a pack where >80% of sprites are A bucket (pack outlier)
- H3: Extreme aspect ratio on a character-classified sprite (possible misclassification)

**E — Tileset:** Tileset sprites routed here pending `SPEC_PENDING_032.md` finalization.
Do not accept tileset sprites into the Golden Dataset until tileset DNA spec is locked.

## Workflow

1. Run `python tools/run_triage_scorer.py` (resumable — safe to kill and restart)
2. Run `python tools/curation_ui.py` → open http://localhost:5001
3. Work through buckets: A first, then D, then B
4. After curation session: `python tools/generate_calibration_report.py`
5. Review `logs/rubric_calibration_report.md` before Phase 4

## Important

- `scores.json` and `curation_log.jsonl` are never deleted — they are audit records
- Sprites in review buckets are **copies** — originals stay in `data/corpus/train/` untouched
- Accepted sprites are copied to `data/golden/` with full provenance in `golden_manifest.json`
- The calibration report must be reviewed before Phase 4 training begins (phase gate)
